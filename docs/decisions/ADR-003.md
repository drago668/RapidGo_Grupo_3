# ADR-003 — Orquestación con Airflow y arranque del stack

> **Estado:** Aceptado (integración real con Spark pendiente)
> **Fecha:** 2026-11-04 · **Release:** v0.3.0-orchestration

## Contexto

La Semana 3 exige orquestar el pipeline con un DAG, dependencias, reintentos, XCom, calidad y un fallo controlado. El streaming Kafka → Spark → Parquet ya funciona; falta la capa de control. Además, el arranque local presentó `Connection refused` por condiciones de carrera (PR #28).

## Opciones consideradas

- **A. Entrypoint automático** (`db migrate` + `users create`): un solo comando, pero falla por CRLF/permisos y duplica migraciones entre webserver y scheduler. Descartada tras los commits `58b2bf5`, `c31765b` y `dbf7e9e`.
- **B. Inicialización manual con `docker compose run`** (elegida): visible, repetible y equivalente en macOS y WSL 2.

## Decisión

1. **Docker Compose** como único punto de entrada: Kafka (KRaft, `rapidgo_demanda_zonas`), producer, Spark Standalone (master + worker), PostgreSQL y Airflow (webserver + scheduler).
2. **Healthchecks** (`pg_isready`, `nc`) y `depends_on: condition: service_healthy` para Kafka, PostgreSQL y Spark Master, eliminando las condiciones de carrera del PR #28.
3. **Airflow 2.7.2 con `LocalExecutor`** y metadatos en PostgreSQL; UI en `localhost:8085`, DAG manual (`schedule=None`).
4. **Inicialización manual** de la base de Airflow:

```bash
docker compose up -d postgres-airflow
docker compose run --rm --no-deps --entrypoint /bin/bash airflow-webserver -c "airflow db migrate"
docker compose run --rm --no-deps --entrypoint /bin/bash airflow-webserver -c "airflow users create --username admin --firstname Admin --lastname User --role Admin --email admin@example.com --password admin"
docker compose up -d airflow-webserver airflow-scheduler
```

5. **DAG `rapid_go`**: 6 etapas lógicas (`trigger_source`, `kafka_ingest`, `submit_spark_job`, `quality_check`, `analizar_alertas_demanda`, `analizar_zonas_saturadas`), con 4 ramas paralelas en ingesta/procesamiento y XCom vía TaskFlow.

## Evidencia

- **PR #28:** `Connection refused` por race conditions; se agregaron healthchecks y `service_healthy`.
- **Run `manual__2026-11-04T13:39:06`:** `success` en 10,06 s; 4 pedidos, calidad OK, 4 críticos y zonas `{CENTRO: 2, NORTE: 1, SUR: 1}`.
- **Fallo y recuperación:** `AirflowException: DAG is missing the start_date parameter` (13:46), corregido; el DAG volvió a importar sin errores.
- **PR #29 (abierto):** agrega `retries=1/20 s` (2/30 s en `kafka_ingest`) y `xcom_push`.

## Consecuencias

- **A favor:** arranque reproducible, orden declarado, UI/logs/XCom y streaming independiente del orquestador.
- **En contra:** la inicialización es manual; PostgreSQL no tiene volumen; el DAG aún simula Kafka/Spark; no hay reintentos en `develop` (PR #29); el topic no se crea con 3 particiones; el healthcheck de Spark usa `nc`, que no existe en la imagen.
